# Synthetic native popup lifecycle checks

Run `dotnet run --project tools/SettingsTooltipChecks -- --output <new-project-local-report.json>`.

This is a native HWND test, not detached/offscreen rendering. It loads the Settings App resources and suppresses WPF's queued default startup action before any Dispatcher pumping by setting the internal `StartupEventArgs.PerformDefaultAction` to false in `Application.Startup`. This test-only reflection is necessary because .NET 10 rejects a null `StartupUri` and its BAML loader rejects a cross-assembly App subclass. Only a synthetic, non-activating owner Window is shown outside the desktop bounds. No production MainWindow, backend client, HID, service operation, installer, or global shortcut is created. The harness registers its exception recorder before the queued App startup; exceptions are recorded as failures and marked handled, and the production App respects the already-handled event.

Hover requests use reflection against the installed .NET 10 WPF `PopupControlService.Current` and `BeginShowToolTip(..., TriggerAction.Mouse)`. WPF creates actual tooltip/popup HWNDs and runs its own timers. Clicks use the production style's routed Click handler; Escape and owner lifecycle events use the synthetic owner. Outside dismissal exercises WPF's lost-capture path with public `Mouse.Capture(null)`; no desktop pointer movement or physical input injection is performed. Private framework API changes fail the harness rather than bypassing checks.

The report records scenario assertions, synchronous and Dispatcher exceptions, HWND observations, startup isolation and mouse capture cleanup. The scenario budget is 40 seconds; an independent 45-second process watchdog writes failure evidence and exits if a synchronous callback stalls. The framework reference is [official .NET 10 WPF PopupControlService source](https://github.com/dotnet/wpf/blob/release/10.0/src/Microsoft.DotNet.Wpf/src/PresentationFramework/System/Windows/Controls/PopupControlService.cs).
